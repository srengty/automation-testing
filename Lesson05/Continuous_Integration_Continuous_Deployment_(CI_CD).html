Part 1: Foundations

What Is CI/CD?

CI/CD is a set of practices that automate how software moves from a developer's commit to running in production, with quality checks at every step.

  • Continuous Integration (CI): Developers merge code frequently; every change is automatically built and tested.
  • Continuous Delivery (CD): Every validated change is automatically prepared and kept ready to release — deployment is a manual click.
  • Continuous Deployment (CD): Every change that passes the pipeline is automatically deployed to production — no human gate.
Automate Integrate Early Release Often

Foundations

Anatomy of a CI/CD Pipeline

A pipeline is an ordered sequence of automated stages triggered by a code change:

  • Source: Commit or pull request triggers the pipeline (webhook).
  • Build: Compile code, resolve dependencies, produce artifacts.
  • Test: Unit, integration, API, UI, and security scans run as quality gates.
  • Package: Build a versioned artifact or container image.
  • Deploy: Release to staging, then production.
  • Operate & Monitor: Observe health; feed signals back to developers.
Source → Build → Test Package → Deploy → Monitor

Why CI/CD Matters

  • Faster feedback: Bugs are caught minutes after a commit, not weeks later.
  • Lower risk: Small, frequent releases are easier to debug and roll back.
  • Higher quality: Automated gates enforce standards consistently.
  • Faster time to market: Features reach users sooner.
  • Reproducibility: Every build is automated and auditable.
  • DORA metrics: Improves deployment frequency, lead time, change-failure rate, and MTTR.
Speed Quality Reliability

Testing in CI/CD

Quality Gates and Fail-Fast

  • Fail fast: Stop the pipeline at the first failed gate to save time and resources.
  • Coverage thresholds: Fail the build if test coverage drops below a target (e.g., 80%).
  • Static quality gates: SonarQube quality gate blocks merges on code smells, bugs, or vulnerabilities.
  • Parallelization: Split test suites across runners to keep feedback under ~10 minutes.
  • Flaky-test handling: Quarantine, retry-with-limit, and track flakiness rather than ignore.
  • Publish artifacts: Always export reports (JUnit XML, HTML) for visibility.

CI/CD Tools

Jenkins — The Extensible Automation Server

Jenkins is the veteran open-source automation server with the largest plugin ecosystem (1,800+ plugins).

  • Pipeline as code: Declarative or scripted Jenkinsfile in Groovy.
  • Plugins: Integrate almost any tool — Git, Docker, Kubernetes, Slack.
  • Distributed builds: Controller + agents for parallel, multi-platform execution.
  • Self-hosted: Full control over infrastructure and data.
  • Blue Ocean / stages view: Visualize pipeline runs.

Jenkins

Declarative Jenkinsfile

// Jenkinsfile (declarative pipeline)
pipeline {
    agent any
    tools { maven 'M3'; jdk 'JDK21' }

    stages {
        stage('Build') {
            steps { sh 'mvn -B clean compile' }
        }
        stage('Test') {
            steps { sh 'mvn test' }
            post {
                always { junit '**/target/surefire-reports/*.xml' }
            }
        }
        stage('Package') {
            steps { sh 'docker build -t myapp:${BUILD_NUMBER} .' }
        }
        stage('Deploy') {
            when { branch 'main' }
            steps { sh './deploy.sh staging' }
        }
    }
    post {
        failure { mail to: 'team@example.com', subject: "Build ${BUILD_NUMBER} failed" }
    }
}

GitLab CI/CD — Built Into the Platform

GitLab CI/CD is natively integrated with the GitLab repository, issues, and registry — no separate server to install.

CI/CD Tools

CircleCI — Cloud-First with Orbs

CircleCI is a cloud-native CI/CD platform known for speed, easy parallelism, and reusable configuration packages.

  • Orbs: Reusable, shareable config packages (e.g., node, aws-cli).
  • Executors: Run jobs in Docker, Linux/Windows/macOS VMs, or Arm.
  • Workflows: Orchestrate jobs with fan-out/fan-in and approval gates.
  • Test splitting: Automatic parallel test distribution by timing.
  • Caching: Dependency and layer caching for fast builds.
Orbs Workflows Test Splitting

CircleCI

.circleci/config.yml

# .circleci/config.yml
version: 2.1
orbs:
  node: circleci/node@5.2.0

jobs:
  test:
    docker:
      - image: cimg/node:20.11
    parallelism: 4
    steps:
      - checkout
      - node/install-packages
      - run:
          name: Run tests (split across 4 containers)
          command: |
            TESTS=$(circleci tests glob "test/**/*.test.js" | circleci tests split)
            npx jest $TESTS --ci
      - store_test_results:
          path: ./reports

workflows:
  build-test-deploy:
    jobs:
      - test
      - hold:
          type: approval
          requires: [test]
      - deploy:
          requires: [hold]
          filters: { branches: { only: main } }

Travis CI — Simple, Convention-Driven

Travis CI popularized hosted CI for open-source projects with a minimal, convention-over-configuration YAML file.

Modern Tooling

GitHub Actions — The Modern Default

GitHub Actions has become the de-facto CI/CD for repos hosted on GitHub: event-driven, marketplace-rich, and matrix-capable.

# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [18, 20]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "${{ matrix.node }}", cache: npm }
      - run: npm ci
      - run: npm test
      - uses: actions/upload-artifact@v4
        with: { name: coverage, path: coverage/ }

Part 4: Advanced Practices

Containers & Orchestration

Containers make builds portable and reproducible — "build once, run anywhere" across the pipeline and production.

  • Docker: Package the app and its dependencies into an immutable image.
  • Registries: Store versioned images (Docker Hub, GHCR, ECR, GitLab Registry).
  • Kubernetes: Orchestrate, scale, and self-heal containerized workloads.
  • Helm: Templated, versioned Kubernetes deployments.
  • Ephemeral build agents: Clean, consistent runners per job.
Docker Kubernetes Helm

Advanced Practices

GitOps — Git as the Source of Truth

GitOps declares the desired state of infrastructure and apps in Git; an agent continuously reconciles the live cluster to match.

  • Declarative: Desired state stored as code in a Git repo.
  • Pull-based deploy: Agents (Argo CD, Flux) pull and apply changes — no cluster credentials in CI.
  • Auto-reconciliation: Drift is detected and corrected automatically.
  • Auditable & revertible: Every change is a Git commit; rollback = git revert.
Argo CD Flux Declarative

Advanced Practices

Infrastructure as Code (IaC)

IaC provisions and configures infrastructure through version-controlled code, eliminating manual, drift-prone setups.

  • Terraform / OpenTofu: Declarative, cloud-agnostic provisioning.
  • Ansible: Configuration management and orchestration.
  • Pulumi: IaC using general-purpose languages (TypeScript, Python, Go).
  • Plan & review: terraform plan as a PR gate before apply.
  • Immutable infrastructure: Replace rather than patch servers.
Terraform Ansible Pulumi

Advanced Practices

DevSecOps — Shift Security Left

Security is embedded as automated gates inside the pipeline rather than a late, manual review.

  • SAST: Static analysis of source code (SonarQube, Semgrep, CodeQL).
  • SCA: Scan dependencies for known CVEs (Dependabot, Snyk, Trivy).
  • DAST: Dynamic scanning of the running app (OWASP ZAP).
  • Secret scanning: Block committed credentials (gitleaks, GitHub secret scanning).
  • Image & IaC scanning: Trivy / Checkov on container images and Terraform.
  • Supply chain: SBOMs, signed artifacts (Sigstore/cosign), SLSA provenance.
SAST / DAST SBOM Signed Artifacts

Observability & Continuous Feedback

A deployment isn't done until you can see how it behaves in production — the loop closes back to developers.

  • Three pillars: Metrics, logs, and distributed traces (OpenTelemetry).
  • Stacks: Prometheus + Grafana, ELK/OpenSearch, Datadog.
  • SLOs & error budgets: Gate deploys on reliability targets.
  • Automated rollback: Trigger on health-check or error-rate spikes.
  • Progressive delivery: Argo Rollouts / Flagger automate canary analysis.

AI and the Next-Gen Pipeline

Modern pipelines increasingly use AI and platform engineering to reduce toil and speed up safe delivery.

Putting It Together

An End-to-End Pipeline

# A modern, test-driven delivery pipeline (GitHub Actions style)
name: deliver
on: { push: { branches: [main] } }
jobs:
  ci:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: mvn -B verify              # unit + integration tests
      - run: npx cypress run            # UI E2E
      - run: trivy fs --exit-code 1 .   # security: SCA + secrets
      - run: docker build -t app:$GITHUB_SHA .
      - run: docker push registry/app:$GITHUB_SHA
  cd:
    needs: ci
    runs-on: ubuntu-latest
    steps:
      - run: argocd app set app --revision $GITHUB_SHA       # GitOps deploy
      - run: ./smoke-test.sh https://prod.example.com        # post-deploy verify
Test → Scan Build → GitOps Verify

Best Practices

CI/CD Principles

  • Commit often, integrate early: Keep branches short-lived; merge to main daily.
  • Keep builds fast: Aim for under ~10 minutes — cache, parallelize, split tests.
  • One artifact, many environments: Build once, promote the same artifact.
  • Everything as code: Pipelines, infra, and config in version control.
  • Fail fast & visible: Surface failures immediately; never ship a red build.
  • Secure by default: Use secrets managers, least privilege, signed artifacts.
  • Automate rollback: Make reverting as easy and fast as deploying.
Fast Repeatable Secure
