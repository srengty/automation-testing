Selenium WebDriver

Wait Strategies and Selectors

Locator strategies: By.id, By.name, By.className, By.cssSelector, By.xpath

// Explicit wait — recommended approach
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(15));

// Wait for element to be clickable
WebElement button = wait.until(
    ExpectedConditions.elementToBeClickable(By.id("submit-btn"))
);
button.click();

// Wait for text to appear
wait.until(ExpectedConditions.textToBePresentInElementLocated(
    By.cssSelector(".status-message"), "Success"
));

// Fluent wait with polling interval
Wait<WebDriver> fluentWait = new FluentWait<>(driver)
    .withTimeout(Duration.ofSeconds(30))
    .pollingEvery(Duration.ofSeconds(2))
    .ignoring(NoSuchElementException.class);

Web UI Testing

Cypress — Modern E2E Testing

Cypress runs inside the browser, giving direct access to the DOM and network layer for fast, reliable tests.

  • In-browser execution: Eliminates network latency between test and browser
  • Auto-retry: Commands automatically retry until the assertion passes
  • Time-travel debugging: Snapshots at every test step
  • Network stubbing: Intercept and mock HTTP requests natively
  • Real-time reload: Tests re-run on file save
  • Component testing: Test React, Vue, Angular components in isolation

describe('Login Flow', () => {
  beforeEach(() => {
    cy.visit('/login');
  });

  it('logs in with valid credentials', () => {
    cy.get('[data-cy="username"]').type('admin@example.com');
    cy.get('[data-cy="password"]').type('secret123');
    cy.get('[data-cy="login-btn"]').click();

    cy.url().should('include', '/dashboard');
    cy.get('.welcome-banner').should('contain', 'Welcome, Admin');
  });

  it('intercepts API and stubs response', () => {
    cy.intercept('POST', '/api/login', { fixture: 'auth-success.json' }).as('loginReq');
    cy.get('[data-cy="login-btn"]').click();
    cy.wait('@loginReq').its('response.statusCode').should('eq', 200);
  });
});

Writing Puppeteer Scripts

const puppeteer = require('puppeteer');

(async () => {
  const browser = await puppeteer.launch({ headless: 'new' });
  const page = await browser.newPage();

  // Navigate and interact
  await page.goto('https://example.com/login');
  await page.type('#username', 'admin@example.com');
  await page.type('#password', 'secret123');
  await page.click('#login-btn');
  await page.waitForNavigation();

  // Take screenshot
  await page.screenshot({ path: 'dashboard.png', fullPage: true });

  // Intercept network requests
  await page.setRequestInterception(true);
  page.on('request', req => {
    if (req.resourceType() === 'image') req.abort();
    else req.continue();
  });

  await browser.close();
})();

REST Assured — Java API Testing

REST Assured provides a domain-specific language for testing REST services in Java with a fluent BDD-style API.

  • Given-When-Then: BDD-style request/response structure
  • JSON Path: Extract and validate nested JSON fields
  • Schema validation: JSON Schema and XML DTD validation
  • Authentication: Basic, Digest, OAuth 1/2, API keys
  • Serialization: POJO serialization with Jackson/Gson
  • Request/Response filters: Logging, auth token injection

REST Assured

Writing REST Assured Tests

<dependency>
    <groupId>io.rest-assured</groupId>
    <artifactId>rest-assured</artifactId>
    <version>5.4.0</version>
</dependency>
import static io.restassured.RestAssured.*;
import static org.hamcrest.Matchers.*;

@Test
void createUserReturns201() {
    String userBody = """
        { "name": "Alice", "email": "alice@example.com" }
        """;

    given()
        .baseUri("https://api.example.com")
        .header("Authorization", "Bearer " + TOKEN)
        .contentType(ContentType.JSON)
        .body(userBody)
    .when()
        .post("/users")
    .then()
        .statusCode(201)
        .body("name", equalTo("Alice"))
        .body("id", notNullValue())
        .body("email", containsString("@example.com"));
}

Part 4: Performance Testing

Apache JMeter

JMeter is an open-source performance testing tool for measuring application behaviour under load via a GUI or CLI.

  • Protocol support: HTTP/S, FTP, JDBC, LDAP, SOAP, REST, WebSocket
  • Thread groups: Simulate concurrent user populations
  • Samplers: Individual requests or transactions to measure
  • Listeners: Summary Report, Aggregate Graph, Response Time Graph
  • Assertions: Validate response content, time, and size
  • Distributed testing: Master-controller and multiple remote agents
GUI + Headless Java Plugin Ecosystem

Apache JMeter

Test Plan Structure and CLI Execution

JMeter Test Plan components:

  • Thread Group: 100 users, ramp-up 30s, 5-minute duration
  • HTTP Request Defaults: Base URL and port shared across samplers
  • HTTP Sampler: GET /api/products, POST /api/orders
  • CSV Data Set Config: Parameterize with external test data
  • Response Assertion: Status code 200, body contains "success"

Performance Testing

Gatling — Code-First Load Testing

Gatling treats performance tests as code using a Scala/Java DSL, enabling version control, peer review, and CI integration out of the box.

  • Simulation as Code: Scala, Java, or Kotlin DSL scripts
  • Reactive engine: Asynchronous, non-blocking — handles thousands of users efficiently
  • Built-in reports: Rich HTML reports generated automatically
  • Maven/Gradle plugin: First-class build tool integration
  • Recorder: HTTP proxy captures real traffic to generate simulations
Scala/Java DSL Reactive CI-Native

Gatling

Writing a Gatling Simulation

// Java DSL (Gatling 3.9+)
import io.gatling.javaapi.core.*;
import io.gatling.javaapi.http.*;
import static io.gatling.javaapi.core.CoreDsl.*;
import static io.gatling.javaapi.http.HttpDsl.*;

public class ApiLoadSimulation extends Simulation {

    HttpProtocolBuilder httpProtocol = http
        .baseUrl("https://api.example.com")
        .acceptHeader("application/json");

    ScenarioBuilder browse = scenario("Browse Products")
        .exec(http("Get Products").get("/products").check(status().is(200)))
        .pause(1, 3)
        .exec(http("Get Product Detail").get("/products/#{id}")
            .check(jsonPath("$.name").exists()));

    { setUp(
        browse.injectOpen(
            rampUsers(50).during(30),
            constantUsersPerSec(10).during(60)
        )
    ).protocols(httpProtocol)
     .assertions(global().responseTime().percentile3().lt(500)); }
}

Flutter Testing

Widget Tests with flutter_test

Widget tests run in a headless Flutter environment — fast and deterministic, no device required.

// test/widget/login_widget_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:my_app/widgets/login_form.dart';

void main() {
  testWidgets('shows error on empty submit', (WidgetTester tester) async {
    await tester.pumpWidget(const MaterialApp(home: LoginForm()));

    // Tap login button without filling fields
    await tester.tap(find.byKey(const Key('login-btn')));
    await tester.pump();

    // Assert validation error is shown
    expect(find.text('Email is required'), findsOneWidget);
    expect(find.text('Password is required'), findsOneWidget);
  });

  testWidgets('navigates to dashboard on valid login', (tester) async {
    await tester.pumpWidget(const MaterialApp(home: LoginForm()));
    await tester.enterText(find.byKey(Key('email')), 'user@test.com');
    await tester.enterText(find.byKey(Key('password')), 'pass123');
    await tester.tap(find.byKey(Key('login-btn')));
    await tester.pumpAndSettle();
    expect(find.byType(DashboardScreen), findsOneWidget);
  });
}

Flutter Testing

Patrol — Native Interactions

Patrol extends Flutter's integration_test to handle native system dialogs, permissions, and deep links.

  • Native automator: Interact with system dialogs and notifications
  • Permission handling: Grant/deny camera, location, push notifications
  • Deep link testing: Navigate via URL schemes
  • patrolTest(): Drop-in replacement for testWidgets()
  • CI support: Android emulator and iOS simulator
// Patrol example — grant camera permission
patrolTest('takes photo with camera permission', ($) async {
  await $.pumpWidgetAndSettle(const MyApp());
  await $.tap(find.byKey(Key('open-camera')));
  
  // Grant native system permission dialog
  if (await $.native.isPermissionDialogVisible()) {
    await $.native.grantPermissionWhenInUse();
  }
  
  await $.tap(find.byKey(Key('capture-btn')));
  expect(find.byType(PhotoPreviewScreen), findsOneWidget);
});

Best Practices

Tool Usage Principles

  • Isolate concerns: Use the right tool for each test type, avoid over-relying on UI tests
  • Tests as code: Version-control test scripts alongside application code
  • Stable selectors: Use data-cy or data-testid attributes, not fragile CSS paths
  • Environment parity: Use environment variables for base URLs and credentials
  • Parallelism: Run independent test suites concurrently in CI to reduce feedback time
  • Fail fast: Smoke tests run first; heavy performance tests run on schedules
  • Observe and report: Always publish test results as pipeline artefacts

Summary

Key Takeaways

  • Selenium remains the cross-browser E2E standard; Cypress and Puppeteer excel for modern JS web apps.
  • Postman is ideal for API exploration and team collaboration; REST Assured for code-first regression suites.
  • JMeter provides a GUI-first approach to load testing; Gatling brings performance testing into the developer workflow.
  • Flutter offers a built-in testing pyramid — unit, widget, and integration — with Patrol for native interactions.
  • All tools integrate into CI/CD pipelines to provide continuous quality signals.
  • Choosing the right tool for the right job is more important than mastering every tool.
