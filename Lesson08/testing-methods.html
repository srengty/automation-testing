Foundations

What Is a Testing Method?

A test does three things — Arrange, Act, Assert. The testing method is the rule used in the Assert step that decides whether the actual result matches the expectation.

@Test
void additionWorks() {
  Calculator calc = new Calculator();   // Arrange
  int result = calc.add(2, 3);          // Act
  assertEquals(5, result);              // Assert (content equals)
}
Key idea: the same value can be verified many ways. Picking the matching method that fits the intent makes tests both strict enough to catch bugs and loose enough to survive harmless change.
Arrange · Act · Assert

Method 1

Content Equals

The strictest check: actual must be exactly equal to expected (by equals()). Best for deterministic values — IDs, counts, totals, status codes, enum results.

@Test
@DisplayName("New user is granted exactly 50 MB")
void newUserQuota() {
  User u = service.register("mara@itc.edu", "pass123");

  // JUnit
  assertEquals(50 * 1024 * 1024, u.getQuotaBytes());

  // AssertJ — fluent
  assertThat(u.getQuotaBytes()).isEqualTo(52_428_800L);
  assertThat(u.getEmail()).isEqualTo("mara@itc.edu");
}
Watch out: equality on objects uses equals()/hashCode(). For value objects, override them (or use a record) so equality compares content, not reference.
isEqualTo · assertEquals

Method 2

Contains / Substring

Verifies a part is present without pinning the whole value. Ideal when surrounding text may change but a key fragment must appear.

// String fragment
String msg = service.uploadTooBig(file);
assertThat(msg).contains("quota exceeded")
               .doesNotContain("stack trace");

// Collection membership
List<String> folders = storage.listFolders(user);
assertThat(folders).contains("Documents", "Photos");

// Hamcrest equivalent
assertThat(msg, containsString("quota exceeded"));
Use when: the message/format is partly dynamic (timestamps, ids) but a stable signal must be present.
contains · containsString

Method 3

Regex Matched

Asserts the value fits a pattern. Perfect for formatted strings whose shape is fixed even though the content varies — emails, UUIDs, share links, dates.

// A generated share link must look like /s/{8 hex chars}
String link = storage.createShareLink(fileId);

// AssertJ
assertThat(link).matches("/s/[0-9a-f]{8}");

// JUnit + java.util.regex
assertTrue(Pattern.matches("/s/[0-9a-f]{8}", link));

// Hamcrest
assertThat(user.getEmail(),
    matchesPattern("^[\\w.+-]+@[\\w-]+\\.[\\w.-]+$"));
matches vs find: matches() requires the whole string to fit. To check a pattern appears somewhere, anchor loosely or use Matcher.find().
matches · matchesPattern

Method 4

Formula Matched

Instead of a hard-coded literal, the expected value is computed from a rule. The test encodes the relationship the code must uphold — great for derived quantities.

// Rule: free space = quota − sum(file sizes)
@Test
void freeSpaceFollowsFormula() {
  storage.upload(user, file(10 * MB));
  storage.upload(user, file(15 * MB));

  long usedExpected = (10 + 15) * MB;          // the formula
  long freeExpected = user.getQuotaBytes() - usedExpected;

  assertThat(storage.usedBytes(user)).isEqualTo(usedExpected);
  assertThat(storage.freeBytes(user)).isEqualTo(freeExpected);
}
Why it's powerful: the assertion stays correct even if inputs change, because expected is derived the same way the spec defines it — not copied from a single run. (Property-based testing pushes this further.)
expected = f(inputs)

Method 5

Predicate / Condition

When no built-in matcher fits, assert an arbitrary boolean condition — a lambda that captures custom business logic.

// AssertJ — matches(Predicate)
assertThat(user)
    .matches(u -> u.getQuotaBytes() >= u.getUsedBytes(),
             "never over quota");

// AssertJ — satisfies(...) for multiple facts
assertThat(savedFile).satisfies(f -> {
    assertThat(f.getOwner()).isEqualTo(user.getId());
    assertThat(f.getName()).isNotBlank();
    assertThat(f.getCreatedAt()).isBeforeOrEqualTo(Instant.now());
});

// JUnit fallback
assertTrue(user.getQuotaBytes() >= user.getUsedBytes());
matches(Predicate) · satisfies

Method 6

Collection Matching

Folder listings and query results are collections. Assert size, membership, order and uniqueness precisely.

List<String> names = storage.list(user, "/Documents");

assertThat(names)
    .hasSize(3)
    .containsExactly("a.txt", "b.txt", "c.txt")  // order matters
    .doesNotHaveDuplicates();

// order-independent
assertThat(names).containsExactlyInAnyOrder("c.txt", "a.txt", "b.txt");

// extract a field from objects, then assert
assertThat(files).extracting(File::getName)
                 .contains("report.pdf");
Pick the strictness: containsExactly (order) vs containsExactlyInAnyOrder vs contains (subset) — match the guarantee your API actually makes.
hasSize · containsExactly · extracting

Method 7

Exception Matching

Failing correctly is a feature. Assert that the right exception type is thrown and carries the right message.

@Test
@DisplayName("Upload beyond quota is rejected")
void overQuotaThrows() {
  QuotaExceededException ex = assertThrows(
      QuotaExceededException.class,
      () -> storage.upload(user, file(60 * MB)));   // quota is 50 MB

  assertThat(ex.getMessage())
      .contains("quota")
      .matches(".*\\d+ *MB.*");          // mentions a size
}

// And the negative: a valid op must NOT throw
assertDoesNotThrow(() -> storage.upload(user, file(5 * MB)));
assertThrows · assertDoesNotThrow

Method 8

Tolerance & Range

Floating-point math and timings are rarely exact. Assert "close enough" with a tolerance, or that a value lies within a range.

// Floating point — never use plain equals on doubles
double usedMb = storage.usedBytes(user) / 1_048_576.0;
assertThat(usedMb).isCloseTo(25.0, within(0.01));     // AssertJ
assertEquals(25.0, usedMb, 0.01);                  // JUnit delta

// Numeric range
assertThat(storage.freeBytes(user))
    .isBetween(0L, user.getQuotaBytes());

// Performance budget
assertThat(elapsedMs).isLessThan(800);
Rule: comparing double/float with exact equality is a classic bug. Always allow an epsilon.
isCloseTo · within · isBetween

Method 9

Schema / JSON Matching

For APIs, assert the response shape, not just one field. Combine path extraction with the methods above.

// Playwright API response → JSON
APIResponse res = request.get("/api/me");
assertThat(res.status()).isEqualTo(200);

JsonObject body = new Gson()
    .fromJson(res.text(), JsonObject.class);

assertThat(body.has("email")).isTrue();          // field present
assertThat(body.get("email").getAsString())
    .matches("^[\\w.+-]+@[\\w.-]+$");              // regex method
assertThat(body.get("quotaBytes").getAsLong())
    .isEqualTo(52_428_800L);                      // content equals
Contract testing: for full schema validation pipe the body into a JSON-Schema validator (e.g. networknt/json-schema-validator) and assert there are zero violations.
shape + fields, together

Method 10

Visual / Snapshot Matching

For UI, compare the rendered page against a stored golden image or a captured snapshot, allowing a small pixel difference.

// Playwright for Java — auto-waiting web assertions
assertThat(page.getByText("My Cloud Storage")).isVisible();
assertThat(page).hasTitle(Pattern.compile("Cloud.*"));   // regex method
assertThat(page.getByTestId("quota-bar"))
    .hasAttribute("aria-valuenow", "50");

// Pixel snapshot — fails if the UI drifts
byte[] shot = page.screenshot();
Allure.addAttachment("dashboard", "image/png",
    new ByteArrayInputStream(shot), ".png");
Note: Playwright's Java assertThat(locator) auto-waits and retries — no manual sleeps. Use it for state; use screenshots for look-and-feel.
web assertions + screenshots

Putting It Together

A Playwright Test Using Many Methods

@Test
void registerAndSeeQuota() {
  page.navigate("http://localhost:8080/register");
  page.getByLabel("Email").fill("sok@itc.edu");
  page.getByLabel("Password").fill("Secret123!");
  page.getByRole(AriaRole.BUTTON,
      new Page.GetByRoleOptions().setName("Sign up")).click();

  // contains
  assertThat(page.getByRole(AriaRole.HEADING))
      .containsText("Welcome");
  // regex
  assertThat(page).hasURL(Pattern.compile(".*/dashboard$"));
  // content equals
  assertThat(page.getByTestId("quota")).hasText("50 MB");
}
One scenario naturally exercises contains, regex and content equals — most real tests blend methods.

Reporting

Reporting with Allure

Wrap logical phases in Allure.step(...) and attach evidence so every assertion is traceable in the report.

@Test
@Epic("Storage") @Feature("Quota") @Severity(SeverityLevel.CRITICAL)
void quotaEnforced() {
  Allure.step("Register user (50 MB)", () -> {
    service.register("lina@itc.edu", "pw");
  });

  Allure.step("Upload beyond quota is rejected", () -> {
    assertThrows(QuotaExceededException.class,
        () -> storage.upload(user, file(60 * MB)));
  });

  Allure.addAttachment("usage.json", storage.usageJson(user));
}

Judgement

Choosing the Right Method

  • Deterministic value? → content equals. Don't be looser than you must.
  • Dynamic surroundings, stable fragment? → contains.
  • Fixed format, variable content? → regex.
  • Value derived from inputs? → formula (compute the expectation).
  • Custom rule? → predicate / satisfies.
  • Floats & timings? → tolerance / range, never exact equals.
  • Error path? → exception matching (type + message).
Goldilocks principle: a good assertion fails when behaviour breaks and only then. Too strict = brittle; too loose = blind.
Strict enough, loose enough

Wrap-Up

Key Takeaways

  • A testing method is the rule that decides pass/fail — choose it deliberately.
  • Master the catalogue: equals, contains, regex, formula, predicate, collection, exception, tolerance, schema, visual.
  • JUnit + AssertJ + Hamcrest express them all; Playwright (Java) brings them to UI & API.

  • Match strictness to the guarantee — strict for deterministic, looser for variable.
